Proposal Architecture: 4 Layers + Companion Controls

                

                
            

            

                

                    

                        
1. Randomized (Obfuscated) Selectors

                        
Every ID and class name is generated per session or deployment (e.g., #cgpa-box → #x7k2q9). Hardcoded extension scrapers find nothing.

                    

                    

                        
2. Honeypots & Decoy API Records

                        
Hidden off-screen DOM containers and fake student API records (ID 999999) that normal users never touch. Any access proves automated scraping.

                    

                    

                        
3. Tripwire Monitoring (WeakSet)

                        
Legitimate DOM nodes are stored in an in-memory WeakSet rather than visible HTML attributes. A MutationObserver catches any unverified node or tampered decoy.

                    

                    

                        
4. Automatic Lockdown Response

                        
Immediately removes sensitive nodes from the DOM, displays a full-screen warning, invalidates the server session, and requires OTP re-login.

                    

                

                

                    
Honest Limitations & Essential Companion Measures

                    

                        Because extensions run inside the user's browser, front-end defenses raise the cost of attack while server-side controls close the loop: OTP / 2FA login, rate-limiting & anomaly detection, short-lived device-bound tokens, minimal data exposure per page, and official Chrome/Edge Web Store takedown reports.
